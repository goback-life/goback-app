# Dedecube Router

Dedecube Router is a Flutter package for advanced route management. It simplifies navigation stack management, supports named routes, and streamlines route transitions. Designed for clarity and modularity, it allows you to define routes, attach middlewares, and pass parameters with minimal boilerplate.

## Installation

Add `dedecube_router` to your dependencies in `pubspec.yaml`:

```yaml
dependencies:
  dedecube_router:
    git:
      url: git@github.com:dedecube/dedecube-router.git
      ref: v0.0.28
```

⚠️ **IMPORTANT** Changes to router configuration (e.g. initialLocation, routes, etc.) require a full application restart. Hot reload does not update these configurations.

## Defining Routes

Routes are defined by implementing the `Routable` interface. This abstraction encapsulates the essential elements of a route (path, name, middlewares, and a page builder) in a single, reusable class.

## Writing a Routable

A **Routable** class encapsulates all the route-related information (such as the URL path, middleware, and page builder). By leveraging code generation with Freezed, you can reduce boilerplate and automatically generate methods for mapping parameters.

For instance, consider the following example of a `HomeRoutable` class:

```dart
@freezed
class HomeRoutable extends Routable<HomeRoutable>
    with _$HomeRoutable {
  factory HomeRoutable.fromJson(Map<String, dynamic> json) =>
      _$HomeRoutableFromJson(json);

  const HomeRoutable._();

  const factory HomeRoutable({
    @Default(0) int id,
  }) = _HomeRoutable;

  @override
  String get path => '/home';

  @override
  List<Middleware> get middlewares => [
        BiometricAuthEnabledMiddleware(),
      ];

  @override
  Map<String, dynamic> get toMap => toJson();

  @override
  HomeRoutable Function(Map<String, dynamic>) get fromMap =>
      HomeRoutable.fromJson;

  @override
  Widget buildPage(BuildContext context, HomeRoutable routeData) {
    return HomePage(id: routeData.id);
  }
}
```

**Freezed Integration:**  
The `@freezed` annotation is used to generate immutable data classes along with JSON serialization methods.

**Route Configuration:**  
The `path` getter defines the URL path for this route (`/home`). You can override this getter to specify any custom path for your screen.

**Middleware Support:**  
The `middlewares` getter returns a list of middleware that should be applied when navigating to this route. 

**Parameter Mapping:**  
Instead of manually mapping parameters, the `toMap` getter returns the JSON representation (generated by Freezed) of the route instance. The `fromMap` getter is used to reconstruct the `HomeRoutable` from a map, enabling automatic parameter extraction.

**Page Builder:**  
The `buildPage` method receives the route data (automatically reconstructed from the `extra` field) and builds the corresponding widget. 

## Passing Extra Parameters 

When you need to pass additional data to your route—such as complex objects or multiple properties—you can take advantage of the `extra` field in combination with the `toMap` and `fromMap` getters. In the `HomeRoutable` example, the `toMap` getter automatically serializes the route's properties (like `id`) into a JSON-compatible map using Freezed. This map is then assigned to the `extra` field, allowing the router to carry along all the necessary data.

When navigating, this extra data is automatically passed along with the route. Later, in the `buildPage` method, the router can reconstruct the original route instance by using the `fromMap` getter. This approach ensures type safety and consistency while reducing manual parameter extraction, making it straightforward to work with both simple and complex parameters across your routes.

## Modal Routes

Dedecube Router makes it easy to display routes as modal bottom sheets without additional boilerplate. To show a route as a modal, simply override the `isModal` getter in your route definition:

```dart
class ProfileSettingsRoute extends RouterRouteContract<ProfileSettingsRoute> with _$ProfileSettingsRoute {
  // ... other code

  @override
  String get path => '/profile';

  @override
  bool get isModal => true; 

  @override
  Widget buildPage(BuildContext context, ProfileSettingsRoute routeData) {
    return ProfileSettingsPage();
  }
}
```

You can further customize modal appearance by overriding the modalSettings property:

```dart
@override
ModalSettings get modalSettings => const ModalSettings(
  isScrollControlled: true,  // Allow the modal to expand to full height
  isDismissible: false,      // Prevent dismissal by tapping outside
  backgroundColor: Colors.black,  // Custom background color
  modalBarrierColor: Colors.black.withOpacity(0.5),  // Custom overlay color
);
```

## Shell Routes

Shell routes allow you to create persistent UI elements that remain visible while the inner content changes. This is particularly useful for implementing navigation patterns like bottom navigation bars, tab bars, or drawer layouts.

For instance, consider the following example of a `MainShellRoutable` class:

```dart
@freezed
class MainShellRoutable extends ShellRoutable<MainShellRoutable> with _$MainShellRoutable {
  factory MainShellRoutable.fromJson(Map<String, dynamic> json) =>
      _$MainShellRoutableFromJson(json);

  const MainShellRoutable._();

  const factory MainShellRoutable({
    @JsonKey(includeFromJson: false)
    @Default([])
    List<Routable> navigationRoutes,
    @JsonKey(includeFromJson: false) 
    @Default([]) List<Routable> tabRoutes,
    @Default(0) int initialIndex,
  }) = _MainShellRoutable;

  @override
  List<Routable> get routes => navigationRoutes + tabRoutes;

  @override
  String get path => '/main_shell';

  @override
  Map<String, dynamic> get toMap => toJson();

  @override
  MainShellRoutable Function(Map<String, dynamic>) get fromMap =>
      MainShellRoutable.fromJson;

  @override
  Widget buildShell(BuildContext context, CustomRouterState state, Widget child) {
    final currentPath = state.fullPath ?? '';

    // Determine which tab is currently selected
    int currentIndex = initialIndex;
    for (int i = 0; i < tabRoutes.length; i++) {
      if (currentPath.contains(tabRoutes[i].path)) {
        currentIndex = i;
        break;
      }
    }

    // Create navigation items from routes
    final items = tabRoutes.map((route) {
      IconData icon = Icons.chat;
      String label = 'Chat';
      if (route is HomeRoutable) {
        icon = Icons.home;
        label = 'Home';
      } else if (route is SettingsRoutable) {
        icon = Icons.settings;
        label = 'Settings';
      }
      return BottomNavigationBarItem(
        icon: Icon(icon),
        label: label,
      );
    }).toList();

    // Return the shell UI with the child route displayed inside
    return Scaffold(
      body: child,
      bottomNavigationBar: BottomNavigationBar(
        currentIndex: currentIndex,
        onTap: (index) {
          if (index < tabRoutes.length) {
            final targetRoute = tabRoutes[index];
            router.go(targetRoute);
          }
        },
        items: items,
      ),
    );
  }
}
```

The `routes` getter returns all child routes that will be displayed within the shell.

The `buildShell` method defines how your shell UI is constructed. It receives the current state and the child widget (the active route's page), allowing you to wrap the child with persistent UI elements.

```dart
  const SignInRoutable(),

  const RecoveryPasswordRoutable(),
  const ResetPasswordRoutable(),
  
  // Shell route with tab navigation

      HomeRoutable(),
      ChatRoutable(),
      SettingsRoutable(),
```

```dart

router.go(const HomeRoutable());
```

## Route Animations

Dedecube Router allows you to easily customize the transition animations between your routes. You can choose from several built-in transitions or define your own custom animation for each route.

## Built-in Transitions

You can specify the transition type for a route by overriding the `transitionType` getter in your route class. Supported values include:

- `PageTransitionType.material` (default): Standard Material page transition.
- `PageTransitionType.noTransition`: No animation between pages.
- `PageTransitionType.fade`: Fade in/out transition.
- `PageTransitionType.custom`: Use your own custom transition.

Example:

```dart
class HomeRoutable extends RouterRouteContract<HomeRoutable> {
  @override
  PageTransitionType get transitionType => PageTransitionType.fade;

  // ...
}
```

## Custom Transitions

For advanced use cases, you can provide a custom transition by overriding the customTransitionBuilder getter:

```dart
class CustomAnimatedRoutable extends RouterRouteContract<CustomAnimatedRoutable> {
  @override
  PageTransitionType get transitionType => PageTransitionType.custom;

  @override
  CustomTransitionPageBuilder get customTransitionBuilder =>
      (context, state, child) => CustomTransitionPage<void>(
            key: state.pageKey,
            child: child,
            transitionsBuilder: (context, animation, secondaryAnimation, child) {
              return ScaleTransition(
                scale: animation,
                child: child,
              );
            },
          );

  // ...
}
```

## Defining Middlewares

Middlewares allow you to intercept and modify the navigation flow in your application. They can be used to perform tasks such as authentication checks, logging, or conditionally redirecting users to different routes. By defining a middleware, you encapsulate the logic that should be executed before or during navigation.

## Writing a Middleware

To write a middleware, implement the `Middleware` interface and override its `handle` method. This method receives the current `BuildContext` and `GoRouterState` so that you can perform asynchronous operations (e.g., checking authentication status or biometric settings). The method should return a `Routable` instance if a redirection is needed, or `null` if the navigation should proceed normally.

For example, the following middleware checks if biometric authentication is enabled and redirects to a specific route if it is:

```dart
class BiometricAuthEnabledMiddleware extends Middleware {
  @override
  Future<Routable?> handle(
    BuildContext context,
    GoRouterState state,
  ) async {
    final biometric = BiometricAuthEnabledStorable();
    final bool value = await biometric.get(defaultValue: false);
    if (value) {
      return BiometricRoutable();
    }
    return null;
  }
}
```

## Attaching Middlewares to Routes

You can attach one or more middlewares to a route by overriding the `middlewares` getter in your `Routable` class. When a route is accessed, Dedecube Router processes the middlewares in the defined order, allowing you to conditionally redirect or modify navigation behavior.

For example, to apply the `BiometricAuthEnabledMiddleware` to a route, you can define your route as follows:

```dart
class DashboardRoutable extends Routable {
  @override
  String get path => '/dashboard';

  @override
  List<Middleware> get middlewares => [
        BiometricAuthEnabledMiddleware(),
      ];

  @override
  Widget Function(BuildContext, GoRouterState) get builder =>
      (context, state) => DashboardPage();
}
```

In this example, whenever navigation to `/dashboard` is attempted, the `BiometricAuthEnabledMiddleware` will be executed. If the middleware returns a redirection (a different `Routable` instance), the router will navigate to that route; otherwise, it will proceed with the intended `/dashboard` route.

## Global Middlewares

In addition to attaching middlewares to individual routes, you can configure middlewares to run on every navigation event by setting them globally in your startup configuration. This is particularly useful for common checks—such as verifying user authentication—that must occur on every route change.

To set up global middlewares, define them in your application's startup configuration. 

```dart
StartupConfig(
    middlewares: [IsAuthenticatedMiddleware()],
  );
```

With this setup, the specified middlewares are executed for every navigation action, ensuring consistent behavior across your application without the need to attach the same middleware to each individual route.

## Environment Parameters

Dedecube Router can be configured via environment parameters to control certain behaviors dynamically.

- **APP_DEBUG_ROUTER_DIAGNOSTICS:**  
  When set to `true`, this parameter enables detailed diagnostic logging for the router. This is especially useful during development, as it prints out navigation events and router state changes to the console.

- **ROUTER_INITIAL_LOCATION:**  
  This parameter allows you to dynamically set the router's initial location. By specifying a valid route path (e.g., `/home`), you can control which screen is displayed when the app starts.

## Navigation Methods

Dedecube Router provides several convenient methods to perform various navigation actions. Each method is designed for a specific scenario, allowing you to manage the navigation stack according to your app's requirements.

## `router.push(route)`

- **Description:**  
  Adds a new page to the navigation stack while preserving the current page.
  
- **Use Case:**  
  Use this method when you want to navigate to a new screen and allow the user to return to the previous page using the back button.
  
- **Example:**  
  Navigating from a list of items to a detail view. For instance, when a user taps on an item in a list, the app pushes the detail screen onto the stack, so pressing the back button will return the user to the list.

## `router.go(route)`

- **Description:**  
  Replaces the entire navigation stack with the new page.
  
- **Use Case:**  
  Use this method when you need to restart the navigation, such as after a login event, ensuring that previous pages are not accessible.
  
- **Example:**  
  After a successful login, the user is taken to the home screen with the entire previous stack cleared, so the user cannot navigate back to the login screen.

## `router.replace(route)`

- **Description:**  
  Replaces only the current page in the navigation stack.
  
- **Use Case:**  
  Use this method when you want to swap out the current screen for a new one without adding a new entry to the history, keeping the rest of the navigation stack intact.
  
- **Example:**  
  When updating a form page with new content, the current page is replaced with the updated version, ensuring that the user does not see duplicate pages in the back stack.

## `router.pushReplacement(route)`

- **Description:**  
  Removes the current page from the navigation stack and then adds the new page.
  
- **Use Case:**  
  Use this method when you want to replace the current screen entirely so that the replaced page is removed from history, while still preserving earlier navigation history.
  
- **Example:**  
  After completing an onboarding process, the onboarding screen is replaced by the main app screen. The user cannot go back to the onboarding screen, but can still navigate to screens that were present before the onboarding started.

## `router.canPop()`

- **Description:**  
  Checks whether there is a route available to be popped off the navigation stack. This method returns a boolean indicating if the navigator has a history entry that can be removed, meaning the "back" action is possible.

- **Use Case:**  
  Use this method to determine when to enable back navigation (e.g., whether to show a back button in the app's UI) or to execute conditional logic before attempting to pop the current page.

- **Example:**  
  Before displaying a back button, you might call `router.canPop()` to confirm that a previous route exists.  
  
```dart
final canNavigateBack = await router.canPop(context: context);
if (canNavigateBack) {
  // Show back button or perform a pop action.
} else {
  // Disable back navigation or show a different UI.
}
```
